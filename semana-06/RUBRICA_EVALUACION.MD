# 📊 Rúbrica de Evaluación - Semana 6

## 🎯 CRUD Completo con Express

### Criterios de Evaluación (100 puntos)

#### 1. **FUNCIONALIDAD DE LA API** (30 puntos)

**Excelente (26-30 pts)**
- ✅ API con 4+ entidades completamente funcionales
- ✅ Todos los endpoints CRUD implementados y funcionando
- ✅ Relaciones entre entidades funcionando perfectamente
- ✅ Validaciones de negocio apropiadas

**Bueno (21-25 pts)**  
- ✅ API con 3 entidades funcionales
- ✅ CRUD básico implementado en todas las entidades
- ✅ Relaciones básicas funcionando
- ⚠️ Algunas validaciones faltantes

**Suficiente (15-20 pts)**
- ✅ API con 2 entidades funcionales  
- ✅ CRUD básico implementado parcialmente
- ⚠️ Relaciones básicas con algunos errores
- ❌ Validaciones mínimas

**Insuficiente (0-14 pts)**
- ❌ API incompleta o no funcional
- ❌ CRUD básico con errores significativos
- ❌ Relaciones no implementadas correctamente

#### 2. **CALIDAD DE CÓDIGO Y ESTRUCTURA** (25 puntos)

**Excelente (23-25 pts)**
- ✅ Estructura de proyecto profesional y organizada
- ✅ Separación clara de responsabilidades (routes/controllers/services)
- ✅ Código limpio, comentado y bien documentado
- ✅ Manejo de errores robusto y consistente

**Bueno (18-22 pts)**
- ✅ Estructura básica organizada
- ✅ Separación de responsabilidades implementada
- ⚠️ Código mayormente limpio con documentación básica
- ⚠️ Manejo de errores básico

**Suficiente (13-17 pts)**
- ⚠️ Estructura básica pero mejorable
- ⚠️ Separación de responsabilidades parcial
- ❌ Código funcional pero poco documentado
- ❌ Manejo de errores mínimo

**Insuficiente (0-12 pts)**
- ❌ Estructura desorganizada
- ❌ Código mezclado sin separación clara
- ❌ Sin documentación ni manejo de errores

#### 3. **BASE DE DATOS Y RELACIONES** (25 puntos)

**Excelente (23-25 pts)**
- ✅ Esquema de BD normalizado y eficiente
- ✅ Relaciones complejas (1:1, 1:N, N:M) implementadas
- ✅ Migraciones aplicadas correctamente
- ✅ Consultas optimizadas con joins e includes

**Bueno (18-22 pts)**
- ✅ Esquema de BD básico y funcional
- ✅ Relaciones básicas (1:N) implementadas
- ✅ Migraciones básicas funcionando
- ⚠️ Consultas funcionales pero no optimizadas

**Suficiente (13-17 pts)**
- ⚠️ Esquema básico con algunos problemas
- ⚠️ Relaciones básicas con errores menores
- ⚠️ Migraciones aplicadas parcialmente
- ❌ Consultas básicas sin optimización

**Insuficiente (0-12 pts)**
- ❌ Esquema mal diseñado o no funcional
- ❌ Relaciones no implementadas correctamente
- ❌ Problemas con migraciones o persistencia

#### 4. **ENTREGA Y DOCUMENTACIÓN** (20 puntos)

**Excelente (18-20 pts)**
- ✅ README completo con instrucciones claras
- ✅ Documentación de API con ejemplos
- ✅ Código funcional en repositorio
- ✅ Entrega puntual y presentación profesional

**Bueno (14-17 pts)**
- ✅ README básico con instrucciones
- ⚠️ Documentación de API básica
- ✅ Código funcional
- ✅ Entrega puntual

**Suficiente (10-13 pts)**
- ⚠️ README mínimo
- ❌ Documentación limitada
- ⚠️ Código funcional con problemas menores
- ⚠️ Entrega con retraso menor

**Insuficiente (0-9 pts)**
- ❌ Sin documentación o muy limitada
- ❌ Código no funcional o incompleto
- ❌ Entrega tardía o no entregado

### 📊 Escala de Calificación Final

- **90-100 pts**: **Excelente** - Dominio completo de CRUD avanzado
- **80-89 pts**: **Bueno** - Implementación sólida con áreas de mejora  
- **70-79 pts**: **Suficiente** - Cumple objetivos básicos
- **0-69 pts**: **Insuficiente** - Requiere refuerzo

### 🎯 Criterios de Aprobación Mínimos

Para aprobar la semana, el estudiante debe:
- [ ] Implementar al menos 3 entidades con CRUD básico
- [ ] Establecer al menos 2 relaciones entre entidades
- [ ] Demostrar funcionalidad con testing manual
- [ ] Entregar documentación básica de setup
